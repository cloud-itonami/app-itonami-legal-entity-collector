# 20261123: NZ 利用制約（設計制約）

- **状態**: Accepted (2026-11-23, Legal)。2026-11-23 owner 決定（BDAA 申請保留、NZBN API 経路のみ）により設計前提を改訂。2026-11-23 Organizer 是正により、BDAA 4.4(3) の根拠付け（法的拘束力を持たないことを明記）と表示／持出しの線を改訂。ファイルは org 慣習（YYYYMMDD-slug.md）に合わせ改名した（旧: ADR-001-nz-bulkdata-usage-constraints.md。blocked-summary の「ADR-001」言及との対応付けのため旧名を残す）。
- **対象**: NZ Companies Office 由来データ（BDAA / Bulk Data Access Agreement を含む）
- **設計前提**: **BDAA は申請しない・保留（owner 判断 2026-11-23）。設計前提は NZBN API 経路のみ**。NZBN API の利用条件は一部確認済み（2026-11-23、別 worker の一次資料確認。詳細は `docs/sources/blocked-summary-20261123.md` の「NZ の節」を参照。再配布の範囲とレート制限は未確認のため、推測で埋めない）。
- **条文（参考情報、適用対象外）**: https://companiesoffice.govt.nz/data-services/ways-to-get-our-data/bulk-data-access-agreement
- **前提**: この ADR は AWAI-3894 の着手前に読む前提の設計制約である。AWAI-3894 の設計・実装は本 ADR の制約に従い、本 ADR に反する実装は行わない。
- **関連**: Linear AWAI-3186（親）、AWAI-3188。`sources/catalog.edn` の `:nz-nzbn` エントリ（現状のまま、NZBN API 経路の条件は推測で決めない）。

## 背景

NZ Companies Office の BulkData は、Bulk Data Access Agreement（BDAA）への同意を前提に提供されるデータセットである。`sources/catalog.edn` の NZ エントリ（`:id :nz-nzbn`、`:blocked-reason`）は、一括データに BDAA 同意が要ること、利用目的を超える場合は NZBN API（登録が必要）を求められることを記録している。

本 ADR の初版（Accepted 2026-11-23, Legal）は、BDAA を設計前提として、その契約条項（第4.4項第3号の DM 禁止、第4.6項の最新化義務、non-sublicensable、Excluded Websites 表示禁止、終了時削除、監査）を NZ BulkData 由来項目の制約として記録した。BDAA の既定解釈は**禁止寄り**（Organizer 指示 2026-11-23、Legal 統合版「NZ確定」、2通目の「禁止寄り」を既定とする）とした。

しかし owner 判断（2026-11-23）により、**NZ は BDAA 申請を保留し、NZBN API 経路のみ**を使うことが決定された。本改訂は設計前提を「BDAA を用いない」ものに置き換え、どの制約が契約条項として適用対象外になり、どの方針が設計制約として残るかを明記するものである。BDAA を締結しないため、同 4.4(3) は法的拘束力を持たない（方針として自ら採用するものであり、「契約違反になるからやらない」ではない）。

## 決定

### 1. 設計前提（owner 決定 2026-11-23）

- **BDAA は申請しない・保留**。BDAA の申請主体（組織・Authorised Person）の選定、契約・登録手続きは本 ADR の範囲外であり、行わない。
- **設計前提は NZBN API 経路のみ**。NZBN API の利用条件（登録・同意・料金・用途制限など）は、本 ADR では確定しない。一部は 2026-11-23 に別 worker が一次資料で確認済みであり、確認結果（確認済み項目と未確認項目の内訳）は `docs/sources/blocked-summary-20261123.md` の「NZ の節」に記録されている。確認できていない項目を推測で決めない。`sources/catalog.edn` の NZ エントリは現状のまま（`:status :planned`、`:terms-verified-on nil`）とする。
- **実データ取得はまだしない**。NZBN API の利用条件が揃うまで、NZ 由来の実データの取得は行わない。本 ADR は NZ データの取得を許可するものではなく、その利用制約を記録するものである。

### 2. BDAA 条項は「BDAA を用いない間は適用対象外」

BDAA の契約条項（第4.4項第3号、第4.6項など、契約条項で縛られるもの）は、BDAA を契約として用いない間は**適用対象外**である。なお BDAA を締結しないため、同 4.4(3) は私たちに法的拘束力を持たない。具体的には以下は、契約上の義務として本プロジェクトに適用しない。

- 第4.4項第3号を契約条項として直接適用すること（同条項は BDAA を締結しないため法的拘束力を持たない。ただし下記 3 の設計制約としての DM 禁止・非渡し方針は据え置きであり、方針として採用するものである）。
- 第4.6項の最新化義務を契約条項として適用すること（アプリ内表示の鮮度管理は下記 3 で方針として据え置く）。
- non-sublicensable（再許諾不可）、Excluded Websites 表示禁止、終了時削除、監査。

なお、BulkData データセットの取得・配布は、設計前提（NZBN API 経路のみ、条件未確認）の範囲内では行わない。BulkData / BDAA の利用を再検討する場合は、本 ADR を先に改訂してから行う。

### 3. 維持する設計制約（BDAA を使わない場合も据え置き）

BDAA を用いない場合も、以下の方針を設計制約として残す。

- **NZ 由来項目はマーケティング・リード獲得に用いない（禁止、既定）。第三者に渡さない（非渡し方針）。エクスポート不可**。BDAA を締結しないため、BDAA 第4.4項第3号（direct marketing 用リストの禁止）は法的拘束力を持たない。本方針は、同じ制約（マーケティング・リード獲得に用いない、第三者に渡さない）を自ら採用するもの（将来 BDAA を締結する場合に備え、公的データの扱いとして妥当であるため）。「契約違反になるからやらない」ではなく「方針としてやらない」。エクスポート不可。第三者への項目渡し・外部送信の経路を作らない。リード生成への流用は禁止（条件付きではなく禁止として扱う）。禁止は既定として扱う。
- **アプリ内表示は可。ただし鮮度管理を行うこと（方針として鮮度を保つ）**。**アプリ内表示と外部への持出しは別**である。BDAA の最新化義務（4.6）に相当する鮮度について、BDAA を用いない間は契約義務としては適用対象外としつつ、方針として鮮度を保つ（鮮度が管理できない表示や古い表示の放置は行わない）。表示が可であることは、外部への持出し（エクスポート・第三者への項目渡し）が可であることを意味しない。エクスポート不可、第三者への項目渡し不可（上記）。
- **出所表示・加工明示は契約要件ではなく、公的データ一般原則として行う**。契約が根拠ではないことを明記した上で、公的データ一般原則として出典の表示（`:source {:attribution ...}`）と加工の明示（`:source {:modified? ...}`）を行う。NZ 固有の契約要件であるかのように記載しない。
- **個人データは初期スコープ外（法人基本情報のみ）**。個人データ（役員・個人事業者・住所など）に該当しうる項目は、ライセンスの可否とは**別の判断**で扱う。初期スコープは法人の基本情報に限定する。役員情報、個人事業者の情報、住所（個人の住所を含むもの）など、個人を特定・接触しうる項目は初期スコープに入れない。NZ の同意があれば自動的に個人データの取り扱いが許されるわけではない。

### 4. 個人データの扱い

個人データ（役員・個人事業者・住所など）に該当しうる項目は、ライセンスの可否とは**別の判断**で扱う。個人情報保護法上の判断を要し、NZ の同意があれば自動的に個人データの取り扱いが許されるわけではない。

- **初期スコープは法人の基本情報に限定する方針**。役員情報、個人事業者の情報、住所（個人の住所を含むもの）など、個人を特定・接触しうる項目は初期スコープに入れない。
- 共通スキーマ（`src/itonami/legal_entity/schema.cljc`）は「個人の情報（氏名・住所・生年月日など）は入れない」を不変条件とする。本 ADR の条番号対応表および初期スコープ限定の方針はこの不変条件を補強する。

## 根拠

- owner 判断 2026-11-23: NZ は BDAA 申請を保留し、NZBN API 経路のみを使う。
- BDAA 条文（NZ Companies Office、参考情報）: https://companiesoffice.govt.nz/data-services/ways-to-get-our-data/bulk-data-access-agreement （第4.4項第3号 = DM 用リスト禁止、第4.6項 = 最新化義務等）。本改訂後は BDAA を契約として用いないため、条文は適用対象外の参考情報であり、同 4.4(3) は法的拘束力を持たない。方針の根拠は自らの採用（将来の BDAA 締結への備え、公的データの扱いとして妥当）である。
- Organizer 指示 2026-11-23（Legal 統合版「NZ確定」）: 既定は禁止寄りの解釈（2通目の「禁止寄り」を既定とする）。
- 既存の不変条件（AWAI-3894 への Legal 落とし込み）のうち、設計制約として維持するもの: (b) マーケティング用途に使わない／第三者に渡さない、(d) 個人データは別判断で初期は法人の基本情報に限定。BDAA 契約条項に基づく (a) データセット自体の配布禁止、(c) 取得物の所在を証跡ディレクトリのみに集約すること（契約終了時の削除に備える）は、BDAA を用いない間は適用対象外である。
- 個人情報保護法の条番号対応表は上記の確定表（2026-11-23）による。

## 影響

- **UI / 機能**: アプリ内表示は可（ただし鮮度管理を方針として行う。BDAA 4.6 の契約義務としては適用対象外であり、方針として鮮度を保つ）。エクスポート不可。第三者への項目渡し・外部送信の経路を作らない（維持する設計制約）。**アプリ内表示と外部への持出しは別**である。リード生成用途への流用を設計段階で遮断する。NZBN API の利用条件（未確認）が確認されるまで、具体的な表示の実現条件・実装は決めない。
- **スキーマ**: `src/itonami/legal_entity/schema.cljc` の ns docstring を同じ前提（BDAA 申請保留・NZBN API 経路のみ、DM 禁止・非渡し方針は据え置き、BDAA 条項の前提を外す）に改める。挙動は変えず、ドキュメント文字列のみの変更とする。
- **取得**: NZBN API の利用条件が揃うまで実データの取得はしない。取得物・証跡の集約は、BDAA 条項の前提ではない通常の証跡管理に従う（取得が始まる段階で検討する）。
- **スコープ**: `sources/catalog.edn` の NZ エントリは現状のまま。本 ADR は NZ データの取得・利用を許可するものではなく、その利用制約を記録するものである。
