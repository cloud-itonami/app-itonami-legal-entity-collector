# ADR-001: NZ BulkData の利用制約（設計制約）

- **状態**: Accepted (2026-11-23, Legal)
- **対象**: NZ Companies Office BulkData（Bulk Data Access Agreement / BDAA）
- **条文**: https://companiesoffice.govt.nz/data-services/ways-to-get-our-data/bulk-data-access-agreement
- **前提**: この ADR は AWAI-3894 の着手前に読む前提の設計制約である。AWAI-3894（NZ BulkData 取り込み、仮称）の設計・実装・取得は本 ADR の制約に従い、本 ADR に反する実装は行わない。
- **関連**: Linear AWAI-3186（親）、AWAI-3188。`sources/catalog.edn` の `:nz-nzbn` エントリ（現状のまま、NZBN API 経路の条件は推測で決めない）。

## 背景

NZ Companies Office の BulkData は、Bulk Data Access Agreement（BDAA）への同意を前提に提供されるデータセットである。`sources/catalog.edn` の NZ エントリ（`:id :nz-nzbn`、`:blocked-reason`）は、一括データに BDAA 同意が要ること、利用目的を超える場合は NZBN API（登録が必要）を求められることを記録している。本 ADR は、この BDAA を本プロジェクトの設計制約として明文化し、実装・取得・表示・運用の各経路で何をしてはいけないかを固定的に記録する。

BDAA の既定解釈は**禁止寄り**とする（Organizer 指示 2026-11-23、Legal 統合版「NZ確定」、2通目の「禁止寄り」を既定とする）。禁止寄りの解釈とは、契約が禁止していない用途まで許容するのではなく、契約が明示的に許容し、かつ本 ADR の条件を満たす用途だけを許容し、それ以外は既定で禁止として扱う立場である。

## 決定

### 1. BDAA の契約上の制約（禁止寄りの既定）

NZ BulkData 由来の項目・データセットは、以下を契約上の制約として継承する。

- **第4.4項第3号（DM 禁止）**: 抽出項目を direct marketing 用リストとして用いることは禁止。根拠は BDAA 第4.4項第3号（direct marketing 用リストの禁止）。本プロジェクトはこれを、マーケティング・リード獲得用途への利用全般の禁止として設計制約に落とす（下記「設計制約」参照）。
- **第4.6項（最新化義務）**: データの最新化（currentness）の維持が義務付けられる。アプリ内表示の可否はこの最新化義務を満たせることを前提とする。
- **non-sublicensable（再許諾不可）**: ライセンスは再許諾（sublicense）可能なものではない。第三者への再配布・再許諾は契約上認められない。
- **Excluded Websites 表示禁止**: 契約が除外するウェブサイト等での表示は禁止の対象として扱う。
- **終了時削除**: 契約終了時には取得物（データセット・抽出物）について削除が義務付けられる。取得物の所在を証跡ディレクトリのみに集約し、一括削除に備える。
- **監査**: 契約上の監査（audit）に対応できる状態を維持する。証跡（evidence）を残し、所在を追跡可能にする。

条文 URL: https://companiesoffice.govt.nz/data-services/ways-to-get-our-data/bulk-data-access-agreement

### 2. 設計制約（実装に落とす形）

- **抽出項目はマーケティング・リード獲得に用いない（禁止、既定）**。BDAA 第4.4項第3号の DM 禁止を根拠とし、リード生成・リスト販売・第三者への項目渡し・外部送信の経路を作らない。エクスポート機能や第三者向けの項目渡し機能から、NZ 由来項目を除くか、NZ 由来を一括して遮断する方向で実装する。禁止は条件付きではなく既定として扱う。
- **アプリ内表示は第4.6項（最新化義務）を満たす場合に限り、事業目的の表示として条件付きで可**。最新化義務を満たせない表示や、最新化の見通しが立たない表示は行わない。**リード生成への流用は禁止**（条件付きではなく禁止として扱う。表示が事業目的の表示であればよいという解釈で、リード生成に転用してはならない）。
- **出所表示・加工明示は契約要件ではなく、公的データ一般原則として行う**。契約に明文化された要件ではないため、契約が根拠ではないことを明記した上で、公的データ一般原則として出典の表示（`:source {:attribution ...}`）と加工の明示（`:source {:modified? ...}`）を行う。NZ 固有の契約要件であるかのように記載しない。
- **NZBN API 経路は条件未確認（推測で埋めない）**。`sources/catalog.edn` の NZ エントリは現状のままとする。NZBN API の利用条件（登録・同意・料金・用途制限など）は一次資料で確認するまで決めない。本 ADR では NZBN API 経路の可否を決めない。
- **取得物の所在は証跡ディレクトリのみに集約する（契約終了時の削除に備える）**。取得物（生ファイル・抽出物・中間ファイル）の所在を証跡ディレクトリ（`docs/evidence/` およびプロジェクトの証跡方針に従う所在）に集約し、契約終了時の削除を一括して実行できる状態にする。証跡ディレクトリ以外にコピーを拡散しない。認知情報（API キー・トークン等）は repo・証跡・ログに書かない。
- **データセット自体を配布しない**。NZ BulkData 由来のデータセット（全体・一部を問わず、加工の有無を問わず）を配布しない。契約上の再許諾不可・再配布不可の制約として扱う。

### 3. 個人データの扱い

個人データ（役員・個人事業者・住所など）に該当しうる項目は、ライセンスの可否とは**別の判断**で扱う。個人情報保護法上の判断を要し、NZ の BDAA の同意があれば自動的に個人データの取り扱いが許されるわけではない。

- **初期スコープは法人の基本情報に限定する方針**。役員情報、個人事業者の情報、住所（個人の住所を含むもの）など、個人を特定・接触しうる項目は初期スコープに入れない。
- 共通スキーマ（`src/itonami/legal_entity/schema.cljc`）は「個人の情報（氏名・住所・生年月日など）は入れない」を不変条件とする。本 ADR の条番号対応表および初期スコープ限定の方針はこの不変条件を補強する。

## 根拠

- BDAA 条文（NZ Companies Office）: https://companiesoffice.govt.nz/data-services/ways-to-get-our-data/bulk-data-access-agreement （第4.4項第3号 = DM 用リスト禁止、第4.6項 = 最新化義務、その他の再許諾不可・Excluded Websites・終了時削除・監査を含む契約全体）。
- Organizer 指示 2026-11-23（Legal 統合版「NZ確定」）: 既定は禁止寄りの解釈（2通目の「禁止寄り」を既定とする）。
- 既存の不変条件（AWAI-3894 への Legal 落とし込み）:
  - (a) データセット自体を配布しない
  - (b) マーケティング用途に使わない／第三者に渡さない
  - (c) 取得物の所在を証跡ディレクトリのみに集約する（契約終了時の削除に備える）
  - (d) 個人データは別判断で初期は法人の基本情報に限定
- 個人情報保護法の条番号対応表は上記の確定表（2026-11-23）による。

## 影響

- **UI / 機能**: NZ 由来データのエクスポート、第三者への項目渡し、外部送信の経路を作らない。リード生成用途の機能（検索結果のリスト化の営業利用等）への流用を設計段階で遮断する。アプリ内表示は第4.6項の最新化義務を満たせる場合に限り、事業目的の表示として条件付きで行う。
- **スキーマ**: `src/itonami/legal_entity/schema.cljc` の ns docstring に、NZ 由来レコードの設計制約を記録する（本 ADR の参照）。挙動は変えず、ドキュメント文字列のみの変更とする。
- **取得・運用**: 取得物の所在は証跡ディレクトリのみに集約し、契約終了時の削除に備える。BDAA の申請主体（組織・Authorised Person）は owner の判断待ち（残件 item 20）であり、本 ADR では決めない。契約・登録手続きは本 ADR の範囲外である。
- **スコープ**: NZBN API 経路の条件は未確認のまま（推測で埋めない）。`sources/catalog.edn` の NZ エントリは現状のまま。本 ADR は NZ BulkData を許可するものではなく、その利用制約を記録するものである。
